# PRD: Ежемесячный анализ обращений граждан по ЦОН (e-Otinish и 1414)

| Параметр | Значение |
|---|---|
| Версия документа | 1.0 |
| Дата | 02.10.2026 |
| Статус | Прототип v1 готов (`con_dashboard.html`), идёт проверка на реальных выгрузках |
| Область | Центры обслуживания населения (ЦОН) и Единый контакт-центр 1414 |

---

## 1. Контекст

Обращения граждан поступают из двух источников:

- **ИС e-Otinish** — письменные обращения: жалобы, заявления, запросы.
- **Колл-центр 1414** — звонки и обращения через контакт-центр.

Обе системы позволяют выгружать данные. Сейчас эти выгрузки не анализируются системно. Нет единой картины того, какие ЦОНы и какие сотрудники чаще других нарушают стандарты оказания госуслуг и Этический кодекс, какие проблемы повторяются и какие меры по ним принимаются.

## 2. Проблема

1. Руководство не видит регулярной картины качества обслуживания в разрезе «филиал → ЦОН → сотрудник».
2. Нарушения конкретных сотрудников выявляются случайно, а не систематически.
3. Системные проблемы (сбои ИС, нехватка окон, изменения стандарта) смешиваются с персональной виной сотрудников.
4. Рекомендации по итогам жалоб не фиксируются в едином формате с ответственными и сроками, поэтому их исполнение не контролируется.

## 3. Цели

| Цель | Как измеряем |
|---|---|
| Ежемесячно получать структурированный анализ обращений | Отчёт формируется за время не более 30 минут после получения выгрузок |
| Выявлять сотрудников с наибольшим числом нарушений стандарта и Этического кодекса | Рейтинг сотрудников с индексом риска и основаниями (конкретными обращениями) |
| Отделять персональную вину от системных проблем | Отдельная группа «Системная проблема», которая не засчитывается сотрудникам |
| Формировать рекомендации и пути решения с ответственными и сроками | Таблица рекомендаций с колонками «Допустившие», «Меры», «Ответственный», «Срок», «Статус» |
| Улучшать качество услуг со временем | Снижение доли обращений с нарушениями и числа повторных обращений месяц к месяцу |

## 4. Пользователи

| Роль | Что делает с отчётом |
|---|---|
| Аналитик / отдел контроля качества | Загружает выгрузки, проверяет распознавание, готовит отчёт |
| Директор филиала, руководители ЦОН | Смотрят рейтинги, принимают решения о мерах |
| Уполномоченный по этике | Работает с нарушениями Этического кодекса, выносит вопросы на Совет по этике |
| Кадровая служба | Использует подтверждённые нарушения в дисциплинарных процедурах и оценке |
| Комплаенс / антикоррупционная служба | Получает обращения с признаками коррупции |
| Методолог филиала, ИТ-служба | Исполняют системные рекомендации (стандарты, база знаний, сбои ИС) |

## 5. Границы проекта

**Входит:**

- анализ обращений только по ЦОНам и линии 1414;
- загрузка выгрузок e-Otinish и 1414 в форматах .xlsx и .csv;
- классификация нарушений, рейтинги, сравнение с прошлым месяцем;
- автоматическая таблица рекомендаций с возможностью редактирования;
- экспорт в CSV и печать / PDF.

**Не входит в v1:**

- прямая интеграция с e-Otinish и 1414 по API (только ручная выгрузка);
- проведение служебных проверок и вынесение решений о виновности (инструмент только даёт сигнал для проверки);
- хранение истории между сеансами (каждый месяц файлы загружаются заново);
- полноценный разбор текстов на казахском языке (словари в основном русскоязычные).

## 6. Ежемесячный процесс

1. Отдел контроля выгружает обращения за отчётный и предыдущий месяц из e-Otinish и 1414.
2. При наличии — выгружает нагрузку сотрудников (количество обслуженных граждан и принятых звонков).
3. Открывает `con_dashboard.html` в браузере, загружает файлы, проверяет сопоставление столбцов.
4. Просматривает разделы, при необходимости уточняет словари нарушений.
5. Редактирует таблицу рекомендаций: уточняет меры, ответственных и сроки.
6. Печатает отчёт или сохраняет в PDF и направляет руководству; рекомендации выгружает в CSV.
7. Сотрудники с жалобами проходят проверку; результаты проверки попадают в поле «Результат рассмотрения» и учитываются в следующем месяце.
8. В следующем месяце контролируется исполнение рекомендаций и динамика по тем же проблемам.

## 7. Источники данных

### 7.1. Поля выгрузки обращений

| Поле | Обязательность | Назначение |
|---|---|---|
| Дата поступления | Обязательно | Отнесение к месяцу, динамика по дням |
| Текст обращения | Обязательно | Классификация нарушений |
| Сотрудник ЦОН (на кого обращение) | Критично для рейтинга | Рейтинг сотрудников |
| ЦОН / отдел | Желательно | Рейтинг ЦОН |
| Филиал / регион | Желательно | Фильтр по филиалу |
| Госуслуга / тематика | Желательно | Анализ тематик и их роста |
| Канал | Желательно | Разделение e-Otinish и 1414 |
| Вид обращения | Опционально | Жалоба, заявление, запрос |
| Исполнитель обращения | Опционально | Контроль сроков рассмотрения |
| Статус | Опционально | Справочно |
| Контрольный срок | Опционально | Выявление просрочек рассмотрения |
| Дата ответа | Опционально | Выявление просрочек рассмотрения |
| Результат рассмотрения | Желательно | Признак подтверждённого нарушения |
| Заявитель (ИИН / телефон) | Опционально | Выявление повторных обращений |
| Номер обращения | Опционально | Ссылка на исходное обращение |

Важно различать два поля: **«Сотрудник ЦОН»** — тот, на кого жалуется гражданин, и **«Исполнитель обращения»** — тот, кто рассматривает жалобу. Нарушения засчитываются первому, просрочки рассмотрения — второму.

### 7.2. Файл нагрузки (опционально)

Два столбца: ФИО сотрудника и количество обслуженных граждан или принятых звонков за месяц. Используется для расчёта жалоб на 1000 обслуживаний. Без нормализации оператор с большой нагрузкой неизбежно получает больше жалоб, чем сотрудник с малой.

## 8. Функциональные требования

### 8.1. Загрузка и распознавание

- **FR-1.** Загрузка нескольких файлов одновременно перетаскиванием или через выбор файла.
- **FR-2.** Поддержка .xlsx (первый лист) и .csv с разделителями `;`, `,` или табуляцией; кодировки UTF-8 и Windows-1251.
- **FR-3.** Автоматический поиск строки заголовков и сопоставление столбцов с полями по ключевым словам в названиях.
- **FR-4.** Ручная корректировка сопоставления для каждого файла с примером значения из столбца.
- **FR-5.** Источник файла (e-Otinish / 1414) определяется по имени файла, по столбцу «Канал» или выбирается вручную.
- **FR-6.** Распознавание дат в форматах `дд.мм.гггг`, `дд.мм.гггг чч:мм`, `гггг-мм-дд` и в числовом формате Excel.
- **FR-7.** Строки без распознанной даты пропускаются; пользователь видит количество пропущенных строк.

### 8.2. Классификация нарушений

- **FR-8.** Обращение относится к виду нарушения, если в тексте или тематике встречается ключевое слово из словаря. Сравнение идёт по началу слова: «груб» находит «грубо», «грубила», но не находит совпадения внутри других слов.
- **FR-9.** Одно обращение может содержать несколько видов нарушений.
- **FR-10.** Просрочка рассмотрения вычисляется автоматически: дата ответа позже контрольного срока, либо ответа нет, а срок уже прошёл.
- **FR-11.** Признак подтверждения определяется по полю «Результат рассмотрения»: «обоснованная», «подтверждено», «приняты меры» — подтверждено; «необоснованная», «не подтвердилось», «отказано» — не подтверждено; остальное — не проверено.
- **FR-12.** Повторные обращения — обращения от заявителей, писавших или звонивших больше одного раза за месяц.

### 8.3. Справочник нарушений (значения по умолчанию)

| Вид нарушения | Группа | Вес | Ответственный за меры | Срок, дней |
|---|---|---|---|---|
| Грубость и неуважительное отношение | Этический кодекс | 3 | Уполномоченный по этике, руководитель ЦОН | 10 |
| Признаки коррупционных проявлений | Этический кодекс | 5 | Комплаенс-служба филиала | 5 |
| Отсутствие на рабочем месте, нарушение графика | Этический кодекс | 2 | Руководитель ЦОН, кадровая служба | 10 |
| Необоснованный отказ в приёме документов | Стандарт госуслуг | 2 | Руководитель ЦОН | 10 |
| Требование документов сверх стандарта | Стандарт госуслуг | 2 | Методолог филиала | 15 |
| Длительное ожидание (очередь, линия 1414) | Стандарт госуслуг | 1 | Руководитель ЦОН, директор филиала | 30 |
| Нарушение срока выдачи результата | Стандарт госуслуг | 1 | Руководитель ЦОН, отдел контроля качества | 15 |
| Неверная консультация, некомпетентность | Стандарт госуслуг | 1 | Методолог филиала, руководитель ЦОН | 30 |
| Ошибки в оформлении документов | Стандарт госуслуг | 1 | Руководитель ЦОН | 15 |
| Технические сбои | Системная проблема | 0 | ИТ-служба филиала | 15 |
| Нарушение срока рассмотрения обращения | Вычисляется по датам | — | Отдел документооборота и контроля | 10 |

- **FR-13.** Названия, веса, группы и ключевые слова редактируются во вкладке «Словари и веса».
- **FR-14.** Настройки сохраняются в JSON-файл и загружаются из него, чтобы использовать одни и те же словари каждый месяц и передавать их коллегам.
- **FR-15.** Есть возврат к исходным настройкам.

### 8.4. Индекс риска

Для каждого обращения:

```
балл обращения = сумма весов видов нарушений (кроме системных)
если нарушение подтверждено проверкой → балл × 2
```

Индекс риска сотрудника или ЦОН — сумма баллов его обращений за месяц. Дополнительно, при наличии нагрузки, показывается число обращений на 1000 обслуживаний.

### 8.5. Разделы отчёта

- **FR-16. Фильтры:** месяц, канал (e-Otinish / 1414 / все), филиал. Все разделы пересчитываются при смене фильтра.
- **FR-17. Обзор месяца:** всего обращений; обращения с признаками нарушений и их доля; нарушения Этического кодекса; нарушения стандарта госуслуг; просрочки рассмотрения; повторные обращения. Для каждого показателя — изменение к прошлому месяцу. Графики: нарушения по видам, обращения по дням в сравнении с прошлым месяцем, топ сотрудников и ЦОН.
- **FR-18. Сотрудники:** рейтинг по индексу риска с колонками «ЦОН», «Обращений», «Этика», «Стандарт», «Подтверждено», «На 1000 обслуживаний», «Индекс риска», «Изменение», «Состав нарушений». Метка «требует проверки» или «есть подтверждённые». Поиск, фильтр по группе нарушений, выгрузка в CSV. По клику — список обращений сотрудника с подсветкой слов-оснований.
- **FR-19. Сроки рассмотрения:** исполнители обращений с наибольшим числом просрочек.
- **FR-20. ЦОНы:** рейтинг ЦОН по индексу риска, доля обращений с нарушениями, изменение к прошлому месяцу, состав нарушений. По клику — обращения по ЦОН.
- **FR-21. Услуги и темы:** топ тематик, наибольший рост к прошлому месяцу, распределение по каналам.
- **FR-22. Обращения:** полный список за месяц с поиском и фильтром по виду нарушения.

### 8.6. Рекомендации и пути решения

- **FR-23.** Таблица формируется автоматически по данным месяца и содержит колонки: «Проблема», «Основание», «Допустившие (предварительно)», «Меры и пути решения», «Ответственный за исполнение», «Срок», «Статус».
- **FR-24.** Правила формирования строк:
  - по каждому выявленному виду нарушения: число случаев, динамика, ЦОН с наибольшим числом случаев, до трёх сотрудников с наибольшим числом нарушений этого вида, типовые меры, ответственный и срок из справочника;
  - для системных проблем в колонке «Допустившие» указывается, что персональной вины нет;
  - если сотрудник не указан — «установить в ходе проверки»;
  - отдельная строка по просрочкам рассмотрения с исполнителями;
  - строка по каждой услуге, где обращений стало на 30% и более больше (при не менее чем 5 обращениях);
  - строка по повторным обращениям.
- **FR-25.** Все ячейки редактируются; строки добавляются и удаляются; статус выбирается из списка: «Новая», «В работе», «Исполнено», «Не исполнено».
- **FR-26.** Выгрузка таблицы рекомендаций в CSV, который открывается в Excel.

### 8.7. Экспорт

- **FR-27.** Печать или сохранение в PDF всех аналитических разделов одним документом; служебные разделы (загрузка, список обращений, настройки) в печать не попадают.
- **FR-28.** CSV-файлы сохраняются с разделителем `;` и меткой UTF-8, чтобы корректно открываться в Excel с русской локалью.

## 10. Правовые и этические ограничения

1. **Жалоба не равна доказанной вине.** Рейтинг сотрудников — сигнал для проверки. В интерфейсе и отчёте лица в колонке «Допустившие» обозначены как предварительные до подтверждения служебной проверкой или решением Совета по этике.
2. **Персональные данные.** Отчёт содержит ФИО сотрудников и тексты обращений. Распространение — ограниченному кругу: руководство, кадровая служба, уполномоченный по этике. По возможности перед загрузкой удалять ИИН, телефоны и адреса граждан, если не нужен анализ повторных обращений.
3. **Признаки коррупции.** Такие обращения передаются в комплаенс-службу; сведения о сотрудниках до завершения проверки не разглашаются.
4. **Справедливость сравнения.** Для сотрудников с разной нагрузкой сравнивается число жалоб на 1000 обслуживаний, а не абсолютное число.

## 11. Ограничения и риски

| Риск | Влияние | Как снижаем |
|---|---|---|
| В выгрузке e-Otinish нет поля с ФИО сотрудника, на которого жалоба | Рейтинг сотрудников пуст, анализ только по ЦОН | Проверить структуру выгрузки; при необходимости добавить поле в регистрационную карточку |
| Классификация по ключевым словам пропускает нестандартные формулировки или даёт ложные совпадения | Неполнота или ошибки в рейтинге | Ежемесячная донастройка словарей; подсветка слов-оснований для ручной проверки |
| Тексты на казахском языке | Нарушения в таких обращениях не распознаются | Дополнить словари казахскими формулировками (v1.1) |
| Разные названия столбцов в выгрузках | Ручная настройка каждый месяц | Настроить автораспознавание под реальные выгрузки |
| Нет данных о нагрузке | Рейтинг в абсолютных числах менее справедлив | Получать нагрузку из системы электронной очереди и 1414 |
| Нет хранения истории | Исполнение рекомендаций контролируется вручную | Сохранять CSV рекомендаций каждый месяц; в v2 — история в инструменте |

## 12. Открытые вопросы

1. Точный перечень и названия столбцов в выгрузках e-Otinish и 1414.
2. Есть ли в выгрузке e-Otinish поле с ФИО сотрудника ЦОН, на которого жалуются, или его нужно извлекать из текста.
3. Источник данных о нагрузке: электронная очередь ЦОН, отчёты 1414, кадровые данные.
4. Как в выгрузке фиксируется результат рассмотрения и какие формулировки используются.
5. Кто утверждает рекомендации и в каком порядке контролируется их исполнение.
6. Нужен ли отчёт на казахском языке.
7. Устраивают ли веса нарушений по умолчанию или их нужно согласовать с уполномоченным по этике.

## 14. Критерии приёмки v1

- Реальные выгрузки e-Otinish и 1414 загружаются, обязательные поля распознаются автоматически или с минимальной ручной правкой.
- Выборочная проверка 50 обращений показывает, что виды нарушений определены корректно не менее чем в 80% случаев.
- Отчёт за месяц формируется и печатается в PDF не более чем за 30 минут.
- Рейтинг сотрудников и ЦОН совпадает с ручным подсчётом на контрольной выборке.
- Таблица рекомендаций содержит ответственных и сроки по каждому выявленному виду нарушения.
